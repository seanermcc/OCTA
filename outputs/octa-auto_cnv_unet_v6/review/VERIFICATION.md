# Verification of original-prediction review

## Automated checks

`VERIFY_REVIEW.cmd` passed **22 checks** using isolated synthetic records. The checks exercise actual Qt widgets and mouse painting, not just file schemas:

- All nine B/C rating combinations, clearing, seed identity, timestamps/source hashes, persistence, and navigation/reopening.
- Manual overlay on/off, no manual list entries or editing, and completion without reconfirmation.
- Deletions, whole-footprint erasing, explicit misses, both-model miss attribution with one footprint, and explicit gross corrections.
- No ratings from browsing, original-outline confirmation, model/seed switching, or manual overlays; no duplicated lesions from accepting both models.
- Undo/Redo across model changes, persistent event history, restored rating/error state, and lossless saved-revision archives.
- Partial work and finishing without negative whole-field labels; concurrent-save protection.
- Native linked coordinates, all eight thickness-boundary pairs and NaNs, and painting in both maps.
- Next-two filtered ordering, asynchronous navigation, cache reuse, stale queued/running cancellation, byte limits, oversized foreground handling, and timing exclusions.

One before/after pass was measured in one process; operating-system disk caches were not controlled. These results do **not** establish a general improvement in uncached loading. The TS336 acquisition requires native processed-volume recovery, accounting for its longer load.

With these three acquisitions as the filtered queue, the first loaded in **0.201 s** and the next two prefetched in **17.377 s**. All three stayed within the cache's byte limit. Subsequent source retrievals took **0.026, 0.014 and 0.013 milliseconds**, respectively. These lookup times exclude GUI rendering and prediction-store creation. The Qt event loop delivered **526 timer ticks**, with a largest observed gap of **0.214 s**, during loading/prefetch. No review records were generated by prefetch. No human time-saving claim is made.

## Review-record interpretation

The current JSON separates `model_ratings`, `regions`, append-only `review_events`, and `active_error_ids`. Each model rating includes acquisition, experiment, seed, timestamp, original output path/hash, and the outputs displayed when the decision occurred. Cleared ratings have a null value.

Error events contain native `[B-scan, start A-line, stop A-line)` runs, original prediction footprints and source hashes, a stable suggestion/region ID, and explicit model/seed attribution. Added human footprints are separate from original predictions. `training_label` is null: even a false-suggestion rejection is review evidence, not an automatically assigned negative training label.

Undo/Redo appends history events and restores current ratings, region state and active error IDs; it does not erase previous events. New saved revisions are bundled in per-acquisition `regions/history/*_revisions.zip` files to avoid excessive exFAT allocation. Original historical JSON revisions remain intact. Browsing sessions are stored separately and never converted into ratings.

The viewer has no training export or inference path. Completion retains unknown tissue and does not approve all visible proposals or manual references. Original-model ratings remain original-model assessments after edits.
